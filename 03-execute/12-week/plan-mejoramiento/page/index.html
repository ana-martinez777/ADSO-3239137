Roles y responsabilidades

El sistema contempla perfiles con responsabilidades diferenciadas para la administración y operación.

Administrador

Responsable de la administración del sistema.

  • Gestiona el catálogo de implementos.
  • Registra y consulta deportistas.
  • Gestiona los entrenadores.
  • Consulta el reporte de implementos más solicitados.

Entrenador

Responsable de las operaciones de préstamo.

  • Registra y consulta deportistas.
  • Registra préstamos y devoluciones.
  • Consulta los implementos disponibles.
  • Consulta los préstamos vencidos.
Reglas de negocio

Control y trazabilidad de las operaciones

Sports Gear aplica reglas para mantener la disponibilidad de los implementos y controlar los préstamos.

  1. Cada deportista puede tener como máximo tres implementos sin devolver y el plazo de cada préstamo es de dos días.
  2. Los deportistas con préstamos vencidos no pueden recibir nuevos implementos hasta realizar las devoluciones pendientes.
  3. Las unidades disponibles siempre deben permanecer entre cero y el total registrado.
  4. La información del implemento registrada en un préstamo se conserva como una copia histórica y no cambia cuando se modifica el catálogo.
  5. Los préstamos y las devoluciones no se eliminan. Los implementos del catálogo utilizan baja lógica.
  6. Las fechas se gestionan en UTC, los mensajes para el usuario se presentan en español y los identificadores del código se mantienen en inglés.
Calidad del sistema

Requisitos no funcionales

Condiciones técnicas que orientan el rendimiento, la seguridad, la integridad y el despliegue de Sports Gear.

Rendimiento

Las búsquedas deben responder en menos de 300 ms con un catálogo de referencia de 5.000 implementos.

Concurrencia

Si dos operadores intentan entregar la última unidad, una operación se confirma y la otra recibe HTTP 409.

Seguridad

Las contraseñas no se transmiten ni almacenan en texto plano y nunca deben aparecer en los registros del sistema.

Errores uniformes

La API utiliza una estructura uniforme para comunicar errores HTTP sin exponer información interna.

Despliegue

El entorno debe iniciar mediante un solo comando y permitir comenzar con la base de datos vacía.
